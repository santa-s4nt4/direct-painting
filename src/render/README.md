# Browser rendering

`createPaintingRenderer(canvas)` shares the editor/output interface: `setProject`, `setLiveStroke` / `receiveLive`, `setView`, `draw`, and `dispose`. The default is `VolumePaintingRenderer` using Three.js WebGL2; `CPUVolumeRenderer` is the fallback. `RGBAScene` and the old `WebGLPaintingRenderer` remain deterministic compatibility references. Interactive rendering does not read GPU pixels back to CPU.

## Spatial strokes

The 3840×3480×3480 box is a visual guide centered at the origin with Y down; it does not clip input or artwork. Source coordinates keep their legacy 3840×2160 origin and may extend beyond it. A recorded orthonormal 3×3 `plane` maps a source point relative to (1920,1080,0) into world coordinates. New strokes use the inverse view rotation, making the working plane face the camera. Saved planes do not change when the view rotates. `points3D` connects two recorded endpoints for Line; its ribbon faces the current camera, with a round end cap even when aligned to the view direction. This is a collection of spatial planar primitives, not a voxel renderer.

Painting and accumulation buffers are 1920×1080. The `/output` presentation canvas uses 1920×1080 when it fits the available viewport and 1280×720 otherwise; its CSS keeps a 16:9 aspect ratio. The default view shows the central Full HD region at 100%. Zoom is 50–500%; pan covers the box height, and roll/pitch/yaw wrap through a full rotation. The same functions transform input, GPU geometry, CPU projected polygons, box clipping and the editor wireframe. See `src/space.js` and `src/view.js`.

`camera-view.js` positions the actual PerspectiveCamera around the origin and calls `lookAt(0,0,0)`, including roll through the up vector. The focal length remains 5000 while orbit distance can vary. `space.js` uses the same distance for projection and inverse input. An active stroke retains its input plane while the camera moves. `camera-motion.js` owns normal / eased MIDI poses with independent position and zoom axes; the server shares timestamped MIDI events with editor/output. Retired rec settings migrate to normal and discard their camera track.

## GPU passes

Move circles, rectangles, outline variants, Trace contours and completed Lines use analytic quads with per-stroke plane transforms. They do not allocate a raster mask per saved layer. A live Move target is 1×1; actual live geometry is analytic as well. Legacy Trail/Return data retains incremental cached mask rendering for compatible playback.

Jobs are sorted by center depth and clipped against the box. Overlapping shapes use the official Spectral.js Analog pigment shader and premultiplied alpha. The first layer, disjoint screen bounds and 100% paint mixing use equivalent source-over blending directly into the current target. Other layers synchronize only the screen region written since the previous buffer swap; both targets are reset correctly on each frame. Offscreen quads are culled. Gaussian passes cover the projected exposure plus their halo, rather than the whole viewport. There is no separate edge color. Gaussian Blur defaults OFF (16px). Motion blur defaults ON (100% shutter = one 60Hz frame, adjustable 0–200%). Both can be toggled independently on the Draw brush or each layer. Shared quarter-resolution Gaussian scratch targets are created only when Blur is first used and reused across layers. Retired glitch/chromatic settings are ignored on import.

Motion blur integrates 8–32 source-time samples (adaptive to motion) into the same analytic fragment shader, averages premultiplied color/alpha, then composites Analog once per layer. Expanded bounds cover the whole exposure. Translation, pressure-driven size and rectangle rotation use actual recorded geometry, including its easing; saved planes keep 3D projection correct. Stationary geometry bypasses sampling. There are no temporal framebuffer histories or per-layer render targets. The CPU fallback averages projected polygons before optional Gaussian Blur. Live input retains at most 32 displayed-head positions within a short history, cleared on stroke change; output builds the same history from transmitted heads. Scrubbing, loop restart and MIDI reset do not reuse pixels from another time.

Global Camera Motion Blur defaults ON (100% shutter), separately from object Motion blur. `camera-exposure.js` combines object source times with 8–16 camera poses and their inverse plane homographies. Bounds reuse each homography to project four corners, clipping only at camera near/far planes before division. The shader evaluates a bounded screen quad, averages once, and composites once, without world-box clipping or per-pixel world transforms. Only a near/far crossing normalizes inverse homogeneous w to 1/camera-depth and enables the depth rejection branch. Normal and Analog programs share the prepared layer uniforms. Normal manual movement uses bounded pose history; MIDI poses are evaluated analytically at exposure times. Camera blur needs no extra framebuffer or target per layer. CPU vector shapes average projected polygons; legacy bitmap layers retain normal playback but camera blur for those layers is GPU-only.

Static circles, Rings and completed circular Traces use screen-space conics during camera exposure, including outside the guide. Each original camera sample still contributes, but its pixel classification avoids the inverse-plane division, shape/color array lookups and source-space rotation. Centering the conic coordinates preserves float32 precision at thin edges. Packed coefficients reuse the existing inverse-matrix uniforms, so this adds no GPU buffer or sample reduction. Moving objects, partial Traces, rectangles and camera-depth crossings retain the general path. `cameraCircleConic` and the inverse-projection browser reference check this equivalence.

Analog and copy programs are compiled and exercised on the existing transparent 1×1 target before playback, including ANGLE/Metal first-draw setup. Projects with multiple layers initialize their second composition target during project updates. The first overlap caused by an orbit therefore creates no shader program or texture. Gaussian targets remain lazy.

Legacy effects without an explicit `motionBlur` flag migrate once to Blur OFF / Motion blur ON, retaining radius. Saves with the new flag retain explicit choices. See `motion-blur.js`, `motion-shader.js`, `effects.js` and the live transport.

A pending Line creates cached Move Ring gestures only for its first-cycle markers. It uses exactly the same easing, pressure-derived size, ring stroke, visibility and release opacity as a normal Circle Ring. On completion and next-cycle handoff those marker caches are dropped; the saved source data remains available for JSON/Undo.

Trace Motion stores a pending gate on a normal Move layer. Its first loop renders the saved Circle/Rectangle motion unchanged; at the same start phase of the next loop it follows the clockwise contour of the largest eased shape. Ring ON draws an outline; Ring OFF sweeps a radial fill between the center and moving contour point, completing a filled circle or rectangle. The Trace takes the configured duration (0.5s by default) with smoothstep ease-in/ease-out and then uses the layer's existing release fade. The shared `trace-motion.js` computes the settled peak, eased progress and exact perimeter head. GPU outlines use analytic arcs/segments; fills intersect shape coverage with two half-planes. Neither allocates a Trace mask or adds a rendering pass. CPU rendering and intersections use the sampled outline or shared convex fill pieces (at most two sectors / four triangles), with subpixel coordinates preserved. A separate screen overlay draws its moving head as a fixed white 15px circle, independent of fill, Analog mixing and layer effects. The head disappears exactly when drawing completes. At the 1280×720 output size, the marker scales with the FHD painting surface. Move/Trace can be switched from either the Motion sidebar control or the compact toolbar below the canvas.

Contour coverage uses screen derivatives to soften only a roughly one-pixel edge at the existing FHD resolution. It adds no supersampling, MSAA, history, full-screen AA pass or scratch target. Partial circular arcs reject the empty radial interior/exterior before computing cap distances. Only color accumulation targets use linear filtering for final downscaling; timestamp-encoded legacy masks remain nearest-filtered. The legacy 2D renderer retains its crisp reference behavior.

At 30fps a 0.5s Trace only presents about 15 head positions. `traceHeadMarkers` joins the previous presentation interval with a short fading sweep in the existing white-marker overlay draw. All geometry is reprojected with the current view, avoiding camera-history ghosts. Circle subdivisions target a 0.4 logical-pixel curve error within the subdivision budget; rectangles split at their exact corners. Offscreen/hidden parts are clipped before emitting points, spacing targets 3.75 FHD pixels, and each Trace has a 256-point budget. Matching short source/wall-clock gaps can span a missed frame up to 100ms; seek, loop, long-gap and reverse discontinuities reset to the nominal window. The point and sweep disappear at draw completion. Intersection dots retain their existing 15px circular footprint.

The marker renderer retains the same shader and one position/alpha vertex buffer. Project updates reserve its small capacity ahead of playback, old GPU storage is disposed when it grows, and active ranges are uploaded without allocating a temporary array for each point. This adds no painting target, texture or extra draw call. CPU fallback uses the same projected points. Painting coverage comparisons hide only Trace-head overlays and verify those overlays separately with pixel continuity, completion and intersection-footprint checks.

Optional Intersections markers test actual 3D face geometry before projecting results to the screen. Coplanar filled shapes produce one representative point in their overlapping area; non-coplanar faces produce a point for each connected portion of their real intersection line. Separate planes that only overlap in projection produce no marker. The Line tool uses its saved 3D centerline, ignoring display stroke width; outline Trace uses its drawn path area, and filled Trace uses only its swept face without extra stroke width. Each white 15px marker starts a configurable one-shot envelope when an intersection appears; defaults are 0s fade-in, 0.2s hold and 0s fade-out. It is hidden whenever its combined layer and envelope alpha is below 50%. Pulse positions stay in world coordinates and are reprojected for the current camera, avoiding screen-space afterimages. The envelope settings are saved and sent to `/output`. Markers are drawn in a sharp screen overlay after Camera motion blur has been composited. Both renderers use `intersections.js` for detection and pulse timing.

Intersection geometry runs on the CPU even with WebGL rendering. `IntersectionDetector` caches faces and world-space pair results, rejects disjoint world/patch bounds and uses a spatial grid for Trace patches. Exact collinear path segments are coalesced without widening their surface. Coplanar overlap centroids come from clipped face polygons with holes subtracted, avoiding the old all-patches/all-path candidate search. Geometry below 50% source alpha is skipped; source visibility also clears held pulses. Camera-only changes reproject cached world points without repeating face intersections. Run `node benchmarks/intersections.mjs --project .direct-painting/loop.json` to measure geometry cost without changing the saved painting.

The editor footer reports measured painting FPS under `SAVED LOCALLY`, sampled every 500ms. It counts successful painting frames, deduplicates forced redraws within a display frame and reports 0 while idle. Its tooltip reports CPU submission time, not GPU execution time. Presentation is capped at 30fps; the displayed number remains an actual measurement rather than the target.

The CPU fallback clips projected vector polygons at camera depth planes and applies the existing alpha-aware blur and Spectral mixer. Filled and outlined Trace both use vector faces, so contours beyond legacy raster coordinates remain visible. Outline capsules share a nonzero-winding fill to avoid overlap holes, and collinear segments are coalesced. Each sample reuses one homography across all polygons. Legacy bitmap strokes keep their original raster extent and use inverse plane homography. GPU context restoration recreates resources from source clips.

## Timing and verification

The application transport is fixed at 16 seconds (120 BPM, 4/4, eight bars) and editor/output presentation is scheduled on a separate 30Hz frame grid. Input, live transport and the 16.7ms Motion/Camera shutter retain their original 60Hz timebase. UI changes request the next painting frame instead of drawing immediately, and output invalidations never reset the presentation limiter. The reusable legacy clock and source renderers still accept arbitrary durations for compatibility tests.

- `npm test`: geometry, project migration, shader-independent math, timing, live transport, MIDI, editing and reference rendering.
- `/benchmarks/gpu-load.html`: cropped composition versus an independent full-frame reference, Circle/Rectangle Trace versus Canvas paths, camera exposure, head completion, mask allocation, disjoint-layer copies and asynchronous GPU timer queries.
- `/benchmarks/volume.html`: current spatial renderer, exact Ring equivalence, rotated input, 3D Line, fallback, and ten active spatial layers.
- `/benchmarks/motion.html`: current temporal-shutter browser checks and ten moving spatial layers (prepared, not run in this environment).
- `npm run test:gles`: production GLSL ES 3.00 link and pixel checks in an ANGLE OpenGL ES 3.0 context. It reproduces the pre-fix precision mismatch, then checks normal and Analog paths. Requires macOS and installed ANGLE libraries; set `ANGLE_LIBRARY_DIR` if needed.
- `npm run test:motion-gpu`: production GLSL pixel comparisons in an offscreen macOS GPU context; it does not validate Three.js/WebGL2 browser integration.
- `/benchmarks/render.html`: legacy GPU versus CPU reference, pigment mixing, Blur, view bounds, cache behavior, context recovery and fallback.
- `npm run test:midi`: actual CoreMIDI virtual-source → host relay integration on macOS.

The earlier, pre-Motion-blur spatial benchmark ([JSON](../../artifacts/volume-render-checks.json)) measured ten 1600px rectangle-ring layers, all visible with Blur16, at mean2.10ms/p95 4.00ms on this Mac Chrome. No saved masks or CPU pixel uploads were created. These are draw timings, not iPad hardware or end-to-end input latency guarantees. See [3D box notes](../../docs/box-canvas.md) and [MIDI transport](../../docs/midi-sync.md).

Current verification: 171 Node tests (including three Happy DOM UI tests), build success, seven native CoreMIDI cases and 17 offscreen shader cases. The eight camera cases have maximum RMS error 0.0334/255, with boundary pixels differing by up to 16/255. Browser automation was unavailable, so actual layout, browser Three.js/WebGL2 integration and iPad performance remain unverified. See [camera behavior and validation](../../docs/camera-motion.md).

Navigation SVGs update only when the view changes. The editor updates transport UI before drawing and schedules its next animation frame first, so a drawing exception cannot cancel subsequent timeline updates. The output frame loop uses the same scheduling order. Camera changes never change the fixed 16-second clock.

The cameraCount uniform is explicitly highp in both stages. Leaving its integer precision implicit made GLSL ES program linking fail (vertex default highp versus fragment default mediump). Desktop CGL did not detect this. The ANGLE regression check now verifies failure before the fix and painted pixels after it; see [the rendering fix](../../docs/shader-precision.md).
