# direct-painting

iPadとApple Pencilで描いた動きを、そのままTouchDesignerへ送るローカル描画ツールです。描画領域は **3840 × 3480 × 3480の3Dボックス**です。向きを変えるたび、画面正面を向いた作業平面へ描きます。初期表示・配信は **1920 × 1080**、タイムラインは **120 BPM・4/4・8小節＝16秒固定** です。旧imagraph-editorとは別のポートと保存領域で動作します。

## 起動

Node.js 22.12以上（または20.19以上）を使用します。

```sh
npm install
npm run dev
```

- PCの編集画面：`http://localhost:5180/`
- Web Render TOP向け映像：`http://localhost:5181/output`
- iPad：PCと同じLANにWi-FiまたはEthernetで接続し、ターミナルに表示される接続先URLをSafariで開きます。

`npm run dev` の起動時には、**Ethernet / 有線LAN** と **Wi-Fi** を区別して、IP・iPad用編集URL・Web Render TOP用URLを表示します。Ethernetで接続する場合は **Ethernet / 有線LAN** の欄にある **iPad / 編集** のURLを開いてください。Macでは実際のハードウェア名から接続方式を判定するので、en0/en1の番号に依存しません。

たとえばEthernetのIPが `192.168.0.2` の場合は、次のように表示されます。

```text
Ethernet [en0] ← Ethernet / 有線LAN
  IP:             192.168.0.2
  iPad / 編集:    http://192.168.0.2:5180/
  Web Render TOP: http://192.168.0.2:5181/output
```

EthernetにIPv4アドレスがない場合は、その旨を表示します。起動後にケーブルを接続した場合やIPが変わった場合は、`npm run dev` を再起動すると最新の接続先を確認できます。

映像ページはUIなしの1920×1080出力です。3D空間から編集画面と同じ角度・範囲を表示します。表示領域が16:9以外の場合は、縦横比を保って黒い余白を付けます。`/render`、旧設定の `/left` と `/right` も同じ単一映像への互換URLです。

## UIと操作

画面上部のタイトルバーと右パネルを廃止し、**左パネル＋キャンバス**の2列にしています。左パネルのタブは次の4つです。

- **Draw**：図形、筆圧によるサイズ範囲、Blur／Motion blur／Camera Motion Blur、Pencil・タッチ入力、リリースフェードを設定します。図形はキャンバス下のツールバーからも直接選べます。
- **Layer**：レイヤー一覧と、選択したレイヤーの塗り・エフェクト・Analog混色・サイズ・形・開始時刻・フェード・トリムを同じタブに表示します。↑／↓で重なり順、目で表示、ゴミ箱で削除を操作します。
- **Files**：Save project、Import projectをまとめています。
- **MIDI**：入力デバイスの切替、頭出しノート番号24、接続状態と受信ノート、Camera motionのON/OFF・反応ノート・ADSRを設定します。

**Clear canvas**とUndo / Redoは左パネル下部に固定され、どのタブを開いても、設定をスクロールしても同じ位置にあります。Undo / Redoは⌘/Ctrl+Z、⌘/Ctrl+Shift+Zでも操作できます。

キャンバス下は **Ellipse / Rectangle / Line｜Ring** です。EllipseとRectangleは移動する円・四角形、Lineは2点を結ぶ直線です。Moveは固定の動作として使い、切替ボタンは表示しません。EllipseとRectangleの切替ではRingのON／OFFを引き継ぎます。Trail / Returnの新規作成は廃止しました。保存済みのレイヤーは互換再生でき、旧ツール選択はMoveへ戻します。Placeとp5.jsの新規作成・編集も廃止しています。

**Ring** は円または四角形の輪郭を描く切り替えです。Shapeの **Rectangle · outline** からも選べます。四角形はRotationの **0° / 45°** プリセットと数値入力で角度を調整し、Strokeで枠の太さを指定します。初期値は正方形で、幅・高さのMaxは1600pxです。Layerからも変更できます。

**Line** は2回のペン入力で直線を作ります。初回の表示は **Circle RingのMoveと同じサイズ・筆圧・追従・リリースフェード** で、離すと消えます。各入力の終点を結び、次の周回の **1点目に触れた時刻** に直線全体が現れます。向きを変えて入力した2点も3D空間で結びます。完成後の線幅は **30px固定** で、保存済みのLineにも適用します。RingのStrokeは初回表示の枠幅です。1点目はCancel first pointで取り消せます。

- **Apple Pencil pressure**：筆圧をMin〜Maxのサイズに反映します。マウスはMaxの固定サイズです。指で描く場合は **Draw with touch** をONにします。
- **Timeline**：再生／一時停止、リスタート、120 BPM／8 BARSの固定表示、シークバー、時間表示をすべて横一列に配置しています。シークすると一時停止します。
- **左パネルの開閉**：キャンバス下のパネルボタンで左側を開閉し、描画面をさらに広げられます。スマートフォン幅ではパネルは引き出し式です。

キャンバスは縦・横のどちらでも1つで16:9を保ちます。編集画面・ライブ配信のフレームレートは **60fps固定** で、変更するUIはありません。

## カラーとキャンバスの拡大縮小

画面右上の **Color** ボタンで、小さな円形カラーパネルを表示・非表示にできます。パネルの外側をタッチすると自動で閉じ、そのタッチで描画やボタン操作も続けられます。円で色相・彩度、下のバーで明るさ・不透明度を設定します。Hex値の入力にも対応します。Drawでは新しいブラシ、Layerでレイヤーを選ぶとその塗り色と不透明度を編集します。グラデーションのBスウォッチを押すとB色を編集できます。

ブラシの直径と矩形の幅・高さは **最大3000px** です。DrawとLayerの両方から指定でき、Apple Pencilの筆圧範囲とJSON保存・ライブ転送にも反映します。

キャンバス上の **2本指で50%〜500%の拡大縮小・パン・ひねり回転** ができます。初期100%はボックス中央の1920×1080です。50%では正面の表示範囲が3840×2160になり、ボックスの上下へパンできます。Draw with touchがOFFでも操作でき、片指を残しても線は描かれません。

キャンバス下のUIにある **回転ボックス** を1本指でドラッグすると、3D空間を一周回転できます。プリセットは **正面** のみです。回転後も新しい図形は画面正面へ描け、既存の図形は描いた角度・奥行きを保持します。

キャンバス下の **− / 倍率 / ＋** でもズームでき、倍率ボタンで **100%・中央・正面** に戻ります。トラックパッドのピンチ、Ctrl＋ホイールも使えます。倍率・位置・角度は **/outputへ即時反映** し、プロジェクトにも保存します。出力は1920×1080のままです。[3Dボックス・Line Ringの操作と検証](docs/box-canvas.md)に詳細を記載しています。

## MIDIで頭出し再生

1. MIDI入力端子のあるオーディオインターフェースを、`npm run dev`を動かす **Mac** に接続します。
2. 左パネルの **MIDI → 入力デバイス（Mac）** で入力を選びます。
3. 頭出しは **MIDIノート番号24に固定** しています。送信機器からノート24を送ってください。受信ノート欄で実際の番号・チャンネルを確認できます。
4. ノート24のNote Onを受けるたび、編集画面と`/output`を **0秒から再生** します。停止中でも再生を始めます。Note Off、ベロシティ0、別ノートは頭出ししません。

**120 BPM × 4/4 × 8小節＝16秒を固定** しています。長い描画、フェード編集、旧プロジェクトの読み込みでも伸びません。MIDI Clockによるテンポ追従は行いません。入力は全チャンネルを対象にします。

MIDIはmacOS CoreMIDIで受けるため、iPadは既存のHTTP／Ethernet接続のまま使えます。iPadへ直接つないだインターフェースはこの入力一覧に現れません。一覧から別の機器を選ぶだけで入力が切り替わります。OFF（入力なし）で入力を止められます。入力の選択はMacへ保存し、再接続時も同じデバイスを選び直します。旧12／36のノート設定は、起動時に24として読み込みます。初回の補助プログラム作成にはXcode Command Line Toolsの`swiftc`が必要です。

[接続・検証・注意点](docs/midi-sync.md)を参照してください。

## カメラの自動移動

キャンバス下の **Camera → normal / midi auto** でモードを選びます。

- **normal**：回転ボックスと2本指操作でカメラを動かします。
- **midi auto**：選択したノートのNote Onで、中心座標を向いたままカメラの方角・高さ・距離をランダムに変えます。Note Offで基準位置へ戻ります。このモードでは回転ボックスと正面ボタンをロックします。

MIDIタブの **Camera motion ON / OFF** はmidi auto／normalの切替と連動します。入力デバイスを選び、使いたいノートを一度送ってから **反応するMIDIノート** の受信済み候補を選んでください。カメラ用ノートと、タイムライン頭出しの固定ノート24は別設定です。カメラにも24を選ぶと、頭出しとカメラ移動が同時に起きます。

**Attack / Decay / Sustain / Release** で動き方を調整します。初期値は **0.4秒 / 0.3秒 / 65% / 0.9秒**。Attackでランダムな位置へ移動し、Decayで基準位置から65%の位置へ戻り、押している間は保持、離すとReleaseで基準位置へ戻ります。途中で次のNote Onを受けても現在位置から滑らかにつながります。ADSRの変更は次のNote Onから適用します。

カメラの設定はプロジェクトに保存され、Macが同じカメラ状態を編集画面と`/output`へ配信します。recは廃止しました。旧recプロジェクトは絵を保持してnormalへ移行し、録画データは読み込みません。詳細と検証範囲は[カメラモーション](docs/camera-motion.md)を参照してください。

## TouchDesigner

Web Render TOPを1つ作り、次のように設定します。

| 項目 | 設定 |
| --- | --- |
| URL or File | `http://localhost:5181/output` |
| Output Resolution | Custom Resolution |
| Resolution | 1920 × 1080 |
| Use Global Res Multiplier | OFF |
| Active / Cook Always | ON |
| プロジェクトのFPS | 60 |

[公式Web Render TOPドキュメント](https://docs.derivative.ca/Web_Render_TOP)に基づく設定です。[TD/direct_painting.py](TD/direct_painting.py)をText DATで実行して同じ構成を作ることもできます。[接続手順](TD/README.md)を参照してください。TouchDesigner本体での実機確認は含みません。

## 保存・読み込み

編集状態はブラウザのIndexedDB（`direct-painting-cache`）と、サーバーの `.direct-painting/loop.json` に自動保存します。元ツールの `.imagraph` とIndexedDBは使用しません。外部サービスには送信しません。

**Files → Save project** で `direct-painting-日時.json` を保存し、**Files → Import project** で端末内のJSONファイルを読み込めます。

旧 `imagraph-project` 形式も読み込めます。左右のレイヤーを1つのキャンバスへ統合し、左右共通レイヤーは1回だけ描画します。左右別の編集があるレイヤーは独立したレイヤーに展開します。座標・サイズ・タイミングは元データの値を保持します。旧Full HDプロジェクトも100%では以前と同じ位置・大きさで表示し、旧10〜800%の表示設定だけを新しい4Kの範囲へ収めます。

## レイヤーエフェクト

DrawタブのEffectsで新しいブラシの設定を、LayerタブのEffectsで既存レイヤーの設定を変更できます。BlurとMotion blurは、それぞれ独立してON/OFFできます。Glitchと色収差は廃止したままです。

- **Blur**：初期 **OFF**、半径16px。ONにすると全方向へぼかします。
- **Motion blur**：初期 **ON**。直近1フレームの移動・サイズ変化・回転を重ね、動く図形の輪郭をにじませます。停止中の図形は鮮明なままです。Shutterは初期100%＝16.7ms、0〜200%で調整できます。

長い残像を蓄積する方式ではありません。シークやMIDI頭出しでも同じ時刻の絵を再現します。完成済みの静止Lineには動きのにじみは発生せず、初回の円Ringはペンの動きに合わせてにじみます。

Draw → Effectsの **Camera Motion Blur** は画面全体に共通のカメラ用エフェクトで、初期 **ON／Shutter 100%＝16.7ms** です。カメラ移動による輪郭のにじみを加え、0〜200%で調整できます。上記のレイヤーごとのMotion blurとは独立しており、静止Lineもカメラが動けばにじみます。

旧ファイルは初回読込時に **Blur OFF／Motion blur ON** へ移行します。元の半径値は保持します。その後に変更したON/OFFとShutterはJSON・自動保存・Undo / Redoに保存され、編集キャンバスと`/output`へ反映します。元の筆跡データを変更しません。混色は **Analogのみ** です。

## GPU描画と3Dビュー

編集画面とWeb Render TOP向け出力は、**Three.js / WebGL2**でGPU描画します。キャンバス下の表示が **60 fps · GPU** ならGPUバックエンドが有効です。WebGL2を利用できない環境ではCPU描画へ切り替わります。

- 全画素をCPUで毎フレーム更新せず、新しく描いた部分だけをGPUへ追加します。フェード・レイヤー合成・グラデーション・混色・レイヤーエフェクトもGPUで処理します。
- 描画済みレイヤーのGPUデータを再利用します。色・エフェクト・タイミングを変更しても、同じ形の描画データは作り直しません。
- レイヤー一覧は軽い行だけを生成し、詳細UIは選択したレイヤーの分だけ作ります。描き始めの全プロジェクト即時送信も省き、入力中のローカル保存を後回しにしています。
- WebGLコンテキストが復帰すると元の描画データから再構築します。JSON保存・Undo / Redoとエフェクト設定を維持しています。

入力・レイヤーデータ・GPU処理を分離し、Three.jsのシーン、カメラ、描画テクスチャを独立させています。PerspectiveCameraと深度付きの描画面を使い、現在は3D空間内の平面へ描画します。立体ブラシや押し出しは含みません。[描画基盤の実装メモ](src/render/README.md)に構成と拡張点を記載しています。

`http://localhost:5180/benchmarks/render.html` で、CPU基準との画素比較、Blurの独立性、拡大縮小と3000pxブラシ、10レイヤー・4K描画領域とFull HD表示のGPU描画時間を測定できます。この検証ページは編集プロジェクトを変更しません。計測は描画処理の比較で、iPad実機の入力遅延や実効FPSを保証する値ではありません。

`/benchmarks/motion.html`にMotion blurとカメラ移動のブラウザー検証ページを用意しています。時間ごとの通常描画との画素比較、ライブ入力、CPUフォールバック、10レイヤー計測を実行できます。Macでは`npm run test:motion-gpu`で実シェーダーのオフスクリーンGPU検証も実行できます。今回の環境ではブラウザー操作機能が利用できず、新しいブラウザー検証と実画面の確認は未実施です。UIのイベント連携は仮想DOMで確認しています。[Motion blur](docs/motion-blur.md)と[カメラモーションの確認範囲](docs/camera-motion.md)を参照してください。

合成コピー・Blurを筆跡周辺へ絞る最適化を維持しています。以前の[Trail負荷調査](docs/trail-performance.md)は旧形式の記録として残しています。Trailの新規作成とFilesの計測入口は現在のUIから外しています。
